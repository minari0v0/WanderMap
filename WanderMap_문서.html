서론 & 개요

한 줄 소개
"스프레드시트로 싸우던 그룹 여행 계획, AI가 동선으로 정리해드립니다."
파편화된 SNS 핫플 정보를 취합하여, LLM 환각 없이 네이버 실시간 데이터 기반으로 짜주는 그룹 동선 플래너.

배경 — 우리가 해결하는 문제

1
흩어진 정보
카카오톡 단톡방의 "여기 가고 싶다" 메시지들 — 수집도 정리도 안 됨
2
수동 동선 정리
구글 스프레드시트에 이동 시간 고려 없이 직접 입력하는 비효율
3
의견 충돌
"맛집파 vs 카페파 vs 관광지파" — 누군가 한 명이 포기
4
한 명이 다 짬
결국 총무 한 명이 모든 계획을 짜고 지쳐버리는 구조

타겟 사용자

구분내용
주 타겟20~30대, 국내외 여행을 즐기는 2~6인 그룹
페인포인트여행 계획 짜는 과정이 번거롭고 의견 조율이 어려움
사용 맥락출발 1주일~1개월 전, 모바일·웹 동시 접근
특징인스타·유튜브에서 핫플을 수집하고 단톡방에 링크만 던지는 세대

핵심 기능

F-01

그룹 방 생성 & 초대

UUID 기반 초대 링크 생성 → 카카오톡/문자 공유 → 클릭 시 로그인 후 자동 합류.

F-02

멤버별 선호도 설문

음식 카테고리, 활동 유형, 기피 장소 키워드, 자유 메모를 각자 독립 제출.

F-03

AI 기반 동선 자동 생성

Gemini는 의도 파악·구조화만 담당. 실제 장소는 Naver 실데이터만 사용해 환각 방지.

F-04

실시간 그룹 투표

WebSocket(STOMP) 기반 👍/👎 투표. 과반수 찬성 시 동선 자동 확정 + 전체 브로드캐스트.

F-05

동선 지도 시각화

확정 장소를 Naver Maps에 번호 핀으로 표시. 경로 라인 렌더링. 핀 클릭 시 지도 앱 연동.

결론 & MVP 범위

MVP 완성 기준 — 6가지 플로우가 막힘없이 동작하면 완성

  • ✓소셜 로그인 — 카카오 또는 구글 OAuth로 로그인/회원가입
  • ✓방 생성 & 초대 — UUID 링크 생성 → 멤버 합류
  • ✓선호도 제출 — 전원 제출 완료 상태 확인
  • ✓AI 동선 생성 — Gemini 구조화 → Naver 실데이터 → 지도 핀 표시
  • ✓실시간 투표 — WebSocket 투표 → 과반수 시 동선 확정
  • ✓동선 확정 뷰 — 최종 일자별 동선을 지도에서 확인

포트폴리오 어필 포인트

POINT 01

AI 아키텍처 설계

LLM 환각을 인지하고 AI 역할을 구조화로만 제한. 실데이터와 분리한 설계 판단력 어필.

POINT 03

최신 스택 운용

Java 25 Virtual Threads + Spring Boot 4.0.6. 최신 LTS 전환 판단과 트레이드오프 설명 가능.

POINT 04

외부 API 통합

Gemini + Naver Local + Directions + Maps 4개 API 통합. Fallback 매트릭스까지 설계.

POINT 05

무료 인프라 운용

일일 한도 설정으로 과금 리스크 제로. 전체 무료로 운용 가능한 아키텍처 설계.

POINT 06

팀 협업 체계

GitHub Actions CI/CD, Swagger 문서 자동화, 역할 분담 설계. 3인 협업 실전 경험.

핵심 유저 플로우 (백엔드 관점)

1
OAuth 소셜 로그인
Provider 인증코드 수신 → AccessToken 교환 → users Upsert → JWT 발급
2
여행 방 생성
POST /api/trips → trips INSERT (status: PLANNING) → invite_code UUID 자동 생성 → trip_members INSERT (OWNER)
3
멤버 합류
POST /api/trips/join/{invite_code} → 유효성 검증 → 중복 방지 → trip_members INSERT (MEMBER)
4
선호도 제출
POST /api/trips/{id}/preferences → 1인 1회 검증 → preferences INSERT → 전원 제출 시 WS 브로드캐스트
5
AI 동선 생성
Gemini API 호출 → Naver Local 검색 → places Upsert(캐싱) → Directions 이동시간 → Greedy TSP → itinerary INSERT → WS 완료 브로드캐스트
6
실시간 투표
WS PUBLISH /app/trip/{id}/vote → place_votes Upsert → 과반수 시 status CONFIRMED → WS 브로드캐스트
7

export const useWebSocket = (tripId: string) => {
  const clientRef = useRef<Client | null>(null);
  const { setStatus, resetRetry } = useWsStore();
  const { updateVote } = useVoteStore();
  const { setStatus: setAiStatus, setGenerating } = useAiStatusStore();
  const queryClient = useQueryClient();

  useEffect(() => {
    const client = new Client({
      webSocketFactory: () => new SockJS(`${import.meta.env.VITE_API_URL}/ws`),
      connectHeaders: { Authorization: `Bearer ${useAuthStore.getState().accessToken}` },

      onConnect: () => {
        setStatus('CONNECTED');
        resetRetry();

        // ① 투표 현황 구독
        client.subscribe(`/topic/trip/${tripId}/votes`, (msg) => {
          const data = JSON.parse(msg.body);
          updateVote(data.itineraryPlaceId, data);
        });

        // ② 동선 확정 변경 → React Query 자동 재조회
        client.subscribe(`/topic/trip/${tripId}/itinerary`, () => {
          queryClient.invalidateQueries({ queryKey: queryKeys.itinerary(tripId) });
        });

        // ③ AI 생성 상태 구독
        client.subscribe(`/topic/trip/${tripId}/ai-status`, (msg) => {
          const data = JSON.parse(msg.body);
          if (data.step === 'COMPLETE') {
            setGenerating(false);
            queryClient.invalidateQueries({ queryKey: queryKeys.itinerary(tripId) });
          } else {
            setAiStatus(data.step, data.progress, data.message);
          }
        });

        // ④ 멤버 변경 구독
        client.subscribe(`/topic/trip/${tripId}/members`, () => {
          queryClient.invalidateQueries({ queryKey: queryKeys.tripMembers(tripId) });
        });
      },
    });

    client.activate();
    clientRef.current = client;
    return () => client.deactivate();
  }, [tripId]);

  const publishVote = useCallback((itineraryPlaceId: number, voteType: 'UP' | 'DOWN') => {
    clientRef.current?.publish({
      destination: `/app/trip/${tripId}/vote`,
      body: JSON.stringify({ itineraryPlaceId, voteType }),
    });
  }, [tripId]);

  return { publishVote };
};

WebSocket 재연결 정책

지수 백오프(Exponential Backoff) — 2초 → 4초 → 8초 순서로 재시도. 3회 초과 시 수동 새로고침 안내.
const MAX_RETRY = 3;
const BASE_DELAY_MS = 2000;

export const useWebSocketReconnect = (connect: () => void) => {
  const { retryCount, incrementRetry, setStatus } = useWsStore();

  const scheduleReconnect = useCallback(() => {
    if (retryCount >= MAX_RETRY) {
      setStatus('DISCONNECTED');
      toast.error('서버 연결이 끊어졌습니다. 페이지를 새로고침 해주세요.');
      return;
    }
    const delay = BASE_DELAY_MS * Math.pow(2, retryCount); // 2s → 4s → 8s
    setStatus('RECONNECTING');
    setTimeout(() => { incrementRetry(); connect(); }, delay);
  }, [retryCount, connect]);

  return { scheduleReconnect };
};

// 재연결 성공 후 상태 복구
onConnect: () => {
  setStatus('CONNECTED');
  resetRetry();
  subscribeAll(tripId);  // 구독 재등록
  // 끊긴 동안 놓친 이벤트 보완
  queryClient.invalidateQueries({ queryKey: queryKeys.itinerary(tripId) });
  queryClient.invalidateQueries({ queryKey: queryKeys.tripMembers(tripId) });
}

PlaceMarkers — diff 기반 마커 관리

// 마커는 naver.maps.Marker 인스턴스를 useRef로 직접 관리
// React 렌더링 사이클과 분리 → 불필요한 마커 재생성 방지
export const PlaceMarkers = ({ map, places, onPlaceClick }) => {
  const markersRef = useRef<Map<number, naver.maps.Marker>>(new Map());

  useEffect(() => {
    const currentIds = new Set(places.map((p) => p.id));

    // 제거된 장소의 마커만 삭제
    markersRef.current.forEach((marker, id) => {
      if (!currentIds.has(id)) { marker.setMap(null); markersRef.current.delete(id); }
    });

    // 새 장소 마커 추가 (기존은 아이콘만 업데이트)
    places.forEach((place, index) => {
      if (markersRef.current.has(place.id)) {
        updateMarkerIcon(markersRef.current.get(place.id)!, place, index);
        return;
      }
      const marker = new naver.maps.Marker({
        map, position: new naver.maps.LatLng(place.latitude, place.longitude),
        icon: createMarkerIcon(index + 1, place.status),
      });
      markersRef.current.set(place.id, marker);
    });
  }, [places, map]);

  return null;
};

  return config;

apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    const original = error.config;
    if (error.response?.status === 401 && !original._retry) {
      original._retry = true;
      try {
        const { data } = await axios.post('/api/auth/refresh', {}, { withCredentials: true });
        useAuthStore.getState().setAuth(data.user, data.accessToken);
        original.headers.Authorization = `Bearer ${data.accessToken}`;
        return apiClient(original);  // 원래 요청 재시도
      } catch {
        useAuthStore.getState().clearAuth();
        window.location.href = '/login';
      }
    }
    return Promise.reject(error);
  }
);

4예산 관리 고도화 — 최소 송금 알고리즘

단순 1/N을 넘어 Greedy 알고리즘으로 최소 송금 횟수 계산. 5명 10건 지출을 최소 이체 횟수로 정산. 카카오페이 딥링크로 바로 송금 화면 이동.

public List<TransferDTO> optimizeTransfers(Map<Long, Long> balances) {
    PriorityQueue creditors = ...; // 많이 받을 사람 우선
    PriorityQueue debtors = ...;   // 많이 줄 사람 우선
    while (!creditors.isEmpty() && !debtors.isEmpty()) {
        var amount = Math.min(creditor.getValue(), -debtor.getValue());
        transfers.add(new TransferDTO(debtor, creditor, amount));
    }
    return transfers;
}
✦ 핵심 포인트 — "최소 이체 횟수" 정산은 기존 정산 앱과의 차별점. 영수증 사진 OCR(Gemini Vision, 3단계) 연동 시 지출 입력 자동화 가능.
