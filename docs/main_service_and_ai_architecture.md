# WanderMap 메인 서비스 및 AI 동선 아키텍처 명세서

> **최근 수정일**: 2026-10-03  
> **문서 상태**: 설계 완료 및 단계별 구현 진행 중  
> **핵심 철학**: **"환각 없는 최신 실데이터 기반의 AI 동선 추천"**과 **"ChatGPT / Claude / Gemini 급의 대화형 워크스페이스 UX"**

본 문서는 WanderMap의 핵심 서비스인 **여행 동선 생성 및 실시간 조율 시스템**, **ChatGPT/Gemini 스타일의 대화형 메인 홈 및 상세 페이지 3단 UI/UX**, 그리고 **Google Search Grounding 기반의 정확도 최우선 Gemini AI 연동 규격**을 상세히 정의합니다.

## 📌 1. 메인 서비스 핵심 개념 및 동선 기획 로직

### 1.1 일자별 여행 동선 설계
사용자가 특정 목적지(예: 일본 오사카, 제주도 등)를 정하고 여행을 계획할 때, WanderMap은 일자별(Day 1, Day 2...)로 현실적이고 유기적인 동선을 구성합니다:

* **Day 1 (도착 및 정착)**:
  - 공항/기차역 도착 ➔ 첫 식사(맛집) ➔ 숙소 체크인 및 짐 보관 ➔ 주변 번화가/야경 산책
* **Day 2 (핵심 관광 및 핫플레이스)**:
  - 기상 및 모닝 카페 ➔ 메인 관광지/문화 명소 ➔ 점심 맛집 ➔ 대중교통으로 연결되는 인기 관광지 또는 근교(예: 오사카 시내에서 나라 사슴공원, 교토 청수사 등) ➔ 디너 ➔ 숙소
* **Day 3 이후**:
  - 멤버들의 선호도와 피로도를 고려한 유동적 동선 및 귀국/체크아웃 연계

### 1.2 AI 추천의 역할과 고도화 지향점
1. **지능적인 지역 확장 및 권역 분석**:
   - 사용자가 단순히 "오사카"라고만 적어도, AI는 오사카 시내 중심(난바, 우메다)뿐만 아니라 간사이 권역(나라 사슴공원, 고베, 교토 등)의 근교 연계 동선까지 지능적으로 추천합니다.
2. **동선 추천의 2가지 진입 경로 (Dual Trigger)**:
   - **경로 A (원클릭 자동 추천 버튼)**: 목적지와 기간을 바탕으로 최적 템플릿 즉시 생성
   - **경로 B (Gemini식 확장형 프롬프트 바)**: *"첫날 난바 숙소 체크인하고 도톤보리 야경 위주로, 둘째 날은 나라 사슴공원 꼭 가고 싶어"*와 같은 세부 요구사항을 전달하여 맞춤 생성
3. **추천 결과 스마트 반영 (3가지 옵션)**:
   - **[전체 반영]**: 기존 일정을 AI 추천 결과로 일괄 덮어쓰기
   - **[부분 반영]**: 추천된 장소 카드 중 원하는 장소만 체크박스로 콕 집어서 내 동선에 삽입
   - **[수정 후 반영]**: 장소 순서나 시간, 메모를 사용자가 다듬은 후 동선에 확정

## 🔍 2. Gemini Grounding: 최신성 + 정확도 최우선 원칙

사용자의 제1원칙: **"무엇보다 정확한 정보가 제일 우선사항. Google 검색과 지도 도구를 통해 최신+정확한 정보를 받아야 함."**

### 2.1 Google Search Grounding 원칙
* Gemini API 호출 시 `tools: [{ google_search: {} }]`를 필수 활성화합니다.
* **실시간 검증**: 장소의 현재 영업 여부, 폐업 여부, 최신 핫플레이스 트렌드, 정확한 현지 주소를 Google 실시간 검색을 통해 크로스체크하여 환각(Hallucination)을 원천 차단합니다.

### 2.2 두 가지 AI 엔드포인트 및 JSON 응답 스키마 분리

AI 연동은 사용자 진입 지점에 따라 **신규 생성(홈 화면)**과 **동선 보완(상세 페이지)** 2개의 별도 엔드포인트로 운영됩니다. 특히 **상세 페이지에서는 사용자가 정한 기존 여행 제목(`title`)이 유지되어야 하므로 응답에 `title`이 포함되지 않으며, 기존 제목을 절대로 덮어쓰지 않습니다.**

#### 2.2.2 [API 2] 세부 일정 (특정 날짜 · 시간 · 장소 맞춤형) AI 추천 (`POST /api/ai/trips/{tripId}/days/{dayNumber}/recommend`)
* **목적**: 이미 생성된 여행 일정 안에서 사용자가 원하는 날짜(`Day N`), 원하는 시간대, 특정 장소/키워드에 대해 맞춤 일정을 추천받는 API입니다.
* **핵심 동작 원칙**:
  1. **전체 일자 컨텍스트 참조**: 요청 시 해당 날짜뿐 아니라 **다른 날짜(`Day 1 ~ Day N`)에 이미 등록된 일정 배열 전체를 LLM에 함께 전달**하여, 이미 방문한 곳과 중복되지 않고 전체 여행 흐름에 자연스럽게 이어지는 코스를 추천합니다.
  2. **[중요] 사용자 검토 후 확정 반영 (Review before Commit)**: 메인 페이지의 전체 초안 AI API(`API 1`)는 초안이므로 즉시 생성·반영되지만, 세부 일정 AI API(`API 2`)는 LLM이 응답한 JSON을 바로 일정에 밀어 넣지 않고 **사용자에게 먼저 추천 후보를 보여준 뒤 추가 확정을 검토받고 반영**합니다.
  3. **기존 여행 제목 보존**: 세부 추천 시에는 기존 여행 방의 제목(`trip.title`)을 덮어쓰지 않고 유지합니다.

### 2.4 AI API 안정성(Retry) · 크레딧 소진 차단 · 환경별 호출 제한(Rate Limit)
무료 LLM API 티어를 안정적으로 운영하기 위해 아래 예외 처리 및 호출 제어 정책을 적용합니다.

1. **일시적 오류 시 최대 3회 재시도 (3x Retry Strategy)**:
   - 네트워크 타임아웃이나 일시적인 LLM 서버 오류(5xx) 응답 시 지수 백오프(Exponential Backoff) 기반으로 **최대 3회까지 자동 재시도**합니다.
2. **크레딧/할당량 소진 시 요청 차단 (Quota Circuit Breaker)**:
   - 크레딧 소진 또는 일일 할당량 초과(`429 Resource Exhausted`) 응답이 감지되면, 상태를 기록하여 **더 이상 추가 AI 요청을 보내지 못하도록 즉시 차단**하고 사용자에게 안내합니다.
3. **상용(Production) vs 로컬(Local) 환경별 호출 횟수 차등 적용**:
   - **상용 서버 (Vercel / Render 호스팅 환경)**: 무료 크레딧 보호를 위해 사용자당 AI 추천 요청을 **하루 1~2회**로 제한합니다.
   - **로컬 개발 환경 (`SPRING_PROFILES_ACTIVE=local`)**: 개발 및 프롬프트 테스트 시에는 **호출 횟수 제한 없이(무제한)** 사용할 수 있도록 분기합니다.

### 2.3 날짜 미지정 시의 안전한 처리 규칙
- 사용자가 프롬프트나 입력란에 구체적인 날짜를 적지 않았다면, **임의의 가짜 날짜를 채우지 않고 `startDate: null`, `endDate: null`로 안전하게 반환**합니다.
- 대신 "3박 4일", "2박 3일" 등 기간 언급에 따라 `Day 1`, `Day 2`... 상대 일정 번호로 구조화하여 상세 페이지에서도 깔끔하게 미정 날짜로 표시됩니다.

## 🎨 3. UI/UX 화면 구성 명세

### 3.1 공통 좌측 사이드바 (ChatGPT / Claude 스타일)
* **공통 유지**: 홈 화면(`/`)과 상세 페이지(`/trips/[tripId]`) 어디에서든 좌측에 고정 유지되어, 언제든 홈으로 나가거나 다른 여행 방으로 즉시 이동 가능.
* **상단**: WanderMap 심볼 로고 + `+ 새 여행 계획하기` 버튼.
* **중앙 (무한 스크롤)**: 내가 생성하거나 참여한 여행 방 목록만 독립적으로 스크롤되는 감성 리스트.
* **하단 고정**: 사용자 닉네임 + `이메일 미인증` 뱃지 + 마이페이지/설정 탭 + 로그아웃.

### 3.2 메인 홈 화면 (대화형 허브)
* **상단 감성 가이드 대형 타이포 문구**:
  - *"설렌 마음 그대로 계획해볼까요?"*
  - *"어디로 떠나나요, {nickname}님?"*
  - *"WanderMap과 함께 그리는 우리만의 지도"*
* **중앙 퀵 칩**: 목적지(도시/지역) 및 일정 선택 칩 (선택 사항).
* **중앙-하단 대형 AI 프롬프트 바 (핵심 킥!)**:
  - ChatGPT/Gemini 스타일의 라운드형 대형 입력창.
  - 전송 시 감성적인 회전 로딩 애니메이션 실행.
  - 결과 생성 완료 시 부드러운 페이드 전환과 함께 **동선 상세 페이지로 자동 이동**.

### 3.3 여행 동선 상세 페이지 (워크스페이스 레이아웃)
* **좌측**: 로그인 회원에게만 공통 사이드바 노출 (공유 링크로 접속한 비로그인 게스트에게는 숨김).
* **중앙 상단 (Google Maps 동선 지도 뷰)**:
  - 컨테이너에 빈 여백 없이 100% 꽉 차게 렌더링되는 Google Maps 동선 뷰 (하단 플로팅 입력창 제거).
  - 번호 마커(`1`, `2`, `3`...)와 이동 경로 연결선 시각화.
* **중앙 하단 (선택된 장소 다이어리 게시글 뷰 - `PlaceDiaryPanel`)**:
  - 우측 리스트에서 장소를 클릭하면 중앙 하단 영역(또는 `크게 보기` 시 중앙 전체 영역)에 해당 장소의 **별점, 한줄평, 마크다운 본문, 인터랙티브 표(Table), 클라우디너리 첨부 사진 갤러리**가 게시글처럼 렌더링됩니다.
* **우측 상단 (참여 멤버 관리 박스 - `MembersBox`)**:
  - **공유 링크 복사**: 원클릭 클립보드 복사.
  - **멤버 표시**: 프로필 아바타, 닉네임, 세련된 `호스트` 배지(VIP 왕관 아이콘 배제), 그리고 비로그인 접속 시 `GUEST (열람 중)` 배지 표시.
* **우측 하단 (원자적 일자별 장소 타임라인 - `ItineraryTimeline`)**:
  - **상단 탭**: `Day 1`, `Day 2`... 탭이 방해 요소 없이 넓게 배치되며, 아래 서브 라인에 해당 일자의 날짜와 요일(`10월 24일 토요일`) 및 `일정 편집` 토글만 깔끔하게 표시(`+ 일자 메모 추가` 제거).
  - **원자적(Atomic) 장소 카드**: 카드 안에는 다이어리 본문을 노출하지 않고 **순서 번호 + 장소명, 위치, 일정 시간(클릭 즉시 수정 가능), 찬반 투표**만 큼직하고 선명한 타이포그래피로 배치.
